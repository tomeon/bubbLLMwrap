You are running inside a bubblewrap sandbox.

## What the sandbox provides
- **Project directory**: mounted read-write at its usual path. Your changes there persist after the session.
- **Version-control metadata**: `.git` and `.jj` directories that existed at launch are read-only, so commits and other commands that write them may fail.
- **Everything else**: a temporary filesystem. Writes outside the project directory and your own configuration directory are discarded when the session ends. Tools come from a read-only `/nix/store`; some host caches and config files are mounted read-only.
- **Network**: requests go through a proxy that allows only a fixed list of domains and rejects the rest. DNS lookups from inside the sandbox do not work.

## What it does not provide
- It does not make your changes safe. The user will build, test, and run this project outside the sandbox, so everything you write will run on their machine.
- Nothing you do is reviewed or logged by the sandbox.

If a task needs network access, files, or tools that are not available, say so instead of trying to work around the sandbox.
